summary: A read whose store call failed is reported as a failure, and only the store's own not-found says something is missing.
category: breaking
dev: STAS-251 made a lost write impossible to hide; this is the mirror half for reads. `AgentLogger.onToolEnd` records a tool call as `tool_error` only when the result carries `isError`, so a read that caught its own store failure and returned plain text was written into the task log — and into automated review and replay — as a successful read that never produced data. Four read helpers in `packages/engine/src/agent-tools.ts` (`readTaskAgentLogs` behind `fn_task_logs_read` and its chat lane, `listArtifactsForAgent`, `viewArtifactForAgent`, `readTaskDocuments` behind `fn_task_document_read`) and the triage lane's own `fn_task_show` / `fn_task_create` copies and the dashboard planning board's `fn_task_show` copy did exactly that. Every one of them now returns `isError: true` composed through STAS-251's single shared loud shape (`storeErrorResult` + `STORE_RETRY_GUIDANCE`), which the dashboard consumes from the engine barrel instead of hand-writing a second failure format, and a store outage is no longer phrased as absence: only the store's own typed `isTaskNotFoundError` may say a card is missing, so a stalled pool can no longer tell an agent its live card vanished. **Callers that previously saw a text result on a failed read now see a failed tool result, and the task log shows that call as `tool_error`.** Guard/validation refusals where nothing was attempted (an unsafe or conflicting read target) and genuinely informative results — `Artifact "…" not found.`, `Document "…" not found.`, `No artifacts found.`, an empty document list — deliberately stay successful text results, because a real absence is a fact about the board and reporting an outage in that shape would teach agents that unavailability deleted their work. A regression test drives the real `AgentLogger.onToolEnd` seam to pin both halves of the rule, and the triage and planning-board copies are pinned against the same assertion so a future edit cannot fix one copy and leave the others lying.
