summary: Stop automatic sweeps from destroying a task worktree and branch while the card that owns them is still in a non-terminal lane.
category: fix
dev: "Ownership, not ancestry, now decides deletion. New `worktree/card-ownership.ts` resolves a workspace (`worktreePath` basename, then canonical branch name, then persisted pointers) to its card and treats only release-lane cards (workflow IR flags `complete`/`humanReview`/`mergeOrchestration`/`mergeBlocker`, legacy `done`/`in-review`, or archived) as release authority. Enforced in one shared funnel, `worktree-backend.removeWorktree`, for the six automatic reasons (`pool-prune`, `step-session-cleanup`, and the four `self-healing-*` reasons): a refusal throws `WorktreeCardOwnershipError` instead of deleting, so the ghost-branch-conflict arm can no longer reach its own `git branch -D`. The idle pool scan additionally protects any `.fusion/worktrees/<card>` directory whose card name matches a non-terminal card, even when that card's `worktree`/`branch` metadata has drifted to null, and an unregistered orphan directory is gated before its recursive delete. The incident shape: a sweep proved a branch 'already landed' by ancestry against the project's local trunk while trunk sat on that card's own unmerged tip, then deleted the checkout and branch of a card parked in `todo` — four times in eight hours, with no `worktree:remove` audit row for any of them. Evidence: every gated decision now writes `worktree:removal-preserved` or `worktree:removed-card-owned` (card id, lane, reason, code path) and a card-log line on release. Coverage so far: the idle scan, the prune sweep, and the eight self-healing removal sites pass a task store, so they are enforced; removal call sites that do not yet supply one (step-session cleanup, acquisition prune, missing-session recovery, pre-execution release, and the raw `git branch -d/-D` sweeps) stay on their old path and are recorded as `worktree:card-ownership-gate-skipped` where an auditor exists — wiring those and replacing ancestry in `reclaimWorktreeOnlyCommits` is the follow-up. A refused removal is a leak, not an error: the workspace stays put and the next terminal-lane cleanup reclaims it.
