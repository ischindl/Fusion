summary: Cards close done only once their commit is proved on the branch they deliver to; --reopen reopens an unproven one.
category: fix
dev: Finalize authorities now gate on `evaluateDefaultBranchLandingProof` (core, pure) measured by a read-only git probe — ancestry of the recorded sha, `git cherry`, or post-image blob identity (squash-safe), with `merge-tree` conflicts as diagnostics only. The yardstick is the resolved integration branch, never `mergeDetails.mergeTargetBranch`, and the branch resolver no longer infers a Fusion task branch as the integration branch. A new landed-truth census (`reconcileLandedTruth`, startup + maintenance batch 1) re-proves cards already in a `done` lane and reports unproven ones (`task:done-landing-unproven`); it is report-only, and the single automatic write clears a `LANDING_PROOF_UNPROVEN:` hold once the work is proven. The backward move is operator-only: `fn task reconcile <id> --reopen` (`task:landing-unproven-reopened`) moves exactly one named card back to its planning lane with the task branch left intact as the recovery source. The shared self-healing complete-lane mover is itself a gated authority — it returns `null` on refusal so its seven recovery arms cannot announce a merge for a card that did not land; workspace cards are exempt (per-repo proof, no singular sha) and an unreadable repository defers rather than refuses. Every probe lane injects one argv-only git runner (`createArgvGitLandingRunner`); no landing call may be rebuilt into a shell string, because the probe's argv carries repository-derived paths. The census also refuses to judge three classes before it probes (`human-terminal-auto-merge-off`, `operator-held`, `pr-backed`, resolved from the live `PrEntity` via `resolveTaskLandingPrVehicleOpen`), and one `sourceMetadata.landedTruthCensus` episode bounds History row, audit row and notice together per refusal window within `LANDED_TRUTH_REPORT_BUDGET`. A second yardstick covers a card whose base branch was a human-named non-task branch (`mergeTargetSource: "task-base-branch"`, e.g. `release`): a commit proven on that ref is delivered (`proofKind: "task-declared-target"`), a target git cannot resolve defers instead of refusing, and a Fusion task branch or a `fusion/groups/` ref is never a delivery vehicle. When both yardsticks are measured absent the refusal stands and its sentence names both refs, so the release card that landed on `release` is never pushed backward while RUFU-294's sibling-branch claim still fails.
