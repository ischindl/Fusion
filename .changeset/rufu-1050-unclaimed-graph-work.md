summary: Retry now recovers cards stuck waiting on planning, instead of refusing them or deleting their spec.
category: fix
dev: A card whose graph continuation waits on planning with no task status was refused by `fn task retry` ("not in a retryable state (status: none)") while the dashboard's Retry ran the destructive restart that deletes `PROMPT.md`. All four Retry surfaces now share one classification, which admits such a card when the new `reconcile-unclaimed-graph-work` self-healing pass has measured it, and re-arms it to `needs-replan` in place. New audit events `task:reconcile-unclaimed-graph-work` (with the delegated authority's own verdict as `outcome`: `repaired` / `announced` / `already-owned` / `authority-refused`) and its withheld half `task:reconcile-unclaimed-graph-work-no-action`, so a card the pass examined and refused is as queryable as one it repaired; new `sourceMetadata.unclaimedGraphWork` episode, cleared by Retry like every other park register. The measured cohort (136 cards, 2026-11-16) resolves to the `behind-drain-window` shape, so this change makes that population repairable and observable; it does not shrink the population, and a drop in the count is NOT an outcome to expect from this change. The execution-lane sibling (a terminal `step-execute` row in the WIP lane) keeps its pre-existing Retry behavior: measured, the generic in-place stage restart still answers it by discarding the checkout metadata and arming the foreach container row, so that repair is a separately scoped change and not delivered here.
