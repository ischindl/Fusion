summary: Scratch-worktree clean-up now removes leftover checkouts registered inside another worktree.
category: fix
dev: Discovery in `cleanupStaleTempMergeWorktrees` and the landing lane's `cleanupLandedTaskWorktree` is now driven by `git worktree list --porcelain` instead of a non-recursive directory listing, so a worktree registered *inside* a scratch tree (created by a `git worktree add` with a relative path from inside the clean-room) is finally visible to the reaper and is removed deepest-first while its parent clean-room is still alive. Containment is an authority rule, not a name filter: only Fusion scratch roots and the exact path a landing just removed may contain a removable registration, and a scratch-shaped registration outside every authority is reported and never touched. The age floor and the live-session / resume-reservation vetoes are unchanged and each deferral is announced. New run-audit rows: `worktree:merge-temp-nested-removed`, `worktree:merge-temp-nested-deferred` and `worktree:post-landing-nested-registration`, plus the `nested-registration`, `outside-containment` and `registration-residue-pruned` reasons on the existing `worktree:tempdir-sweep` row; metadata stays ids/counts/fixed enums and paths stay in the engine log. Measured finding: this leak consumed no `maxWorktrees` unit — worktree capacity derives from persisted task rows, not from the registration inventory — so what the fix buys is an honest `git worktree list`, bounded `.git/worktrees/` admin growth in the shared common dir, and no phantom entries pointing at deleted paths.
