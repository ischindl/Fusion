summary: A tool call whose write never reached the task store now returns a flagged failure with retry guidance.
category: fix
dev: One failure shape for every attempted-and-failed store write — `storeErrorResult` (code `STORE_UNAVAILABLE`, text ending `Retry the call; if it fails again`) for an outage, `storeWriteFailure` (code `STORE_REFUSAL`) when the store refused the operation on purpose; the split is the observation record `storeWriteFailure` (stage: tool write-path, outcome: refusal-vs-outage classified by the domain-phrase test). 21 registered tools across engine, dashboard planner and the CLI extension now return that shape with `isError: true`. Two guards hold it: `tool-write-failure-boundary.test.ts` scans the registration surfaces for an attempted write reporting its failure as a success row or hand-composing a store-failure shell, and `tool-write-failure-boundary-drive.test.ts` imports the real registration modules, drives every exported `fn_` tool's own handler with a store that refuses every write verb and answers reads in two stances, pins the per-tool outcome so a refusal cannot become a silent no-op, and refuses to report a lane as clean without saying which store it ran against. Guard-red-at-base: the drive fails at 57/41 unflagged sites before the conversion. Reconciliation of STAS-251's "message send" claim: the claim was right about the site it fixed — at this branch's base `fn_send_message`'s `catch` already carried `isError` — so the code was not wrong and the stale anchor in the card text pointed at that fixed catch. What the claim overstated was the tool: the same tool's `parked` outcome, the branch that runs once the bounded delivery retry budget is exhausted, still answered `ERROR: Failed to send message: …` as a success row, and `fn_post_room_message` had the same parked branch. STAS-251's wording is corrected in place to name that gap. Re-derived rather than inherited, the write surface was not the four unflagged sites the card listed — all four already carried `isError`. Only two sites were genuinely silent rows: `fn_send_message`'s parked-delivery outcome and `fn_spawn_agent`'s agent-session throw. The other 28 of this branch's 30 converted failure branches — across engine, CLI and dashboard — were loud but hand-composed, so each carried its own copy of a shape agents learn once.
